# R05 — Redis et exploitation locale

Sous-tâches de la story R05 du [sprint S0-R](../SPRINT-00R-SCRUM.md). Lire le [contrat de travail de l’agent](../AGENT-TASKS.md) avant exécution. Ces fiches sont des plans, pas des travaux réalisés.

**Une invocation = une seule sous-tâche.** Le titre de story R05 ne constitue pas une autorisation de tout réaliser en une fois. Les contrôles communs et critères de la story restent applicables.

## R05.01

**Titre de commit proposé :** feat(cache): isolate Redis cache connections

- **Entrée :** R04.06.
- **Travail limité :** Configurer le client Redis disponible, les connexions et préfixes du cache par environnement ; laisser sessions et queue inchangées.
- **Validation exigée :** Lecture/expiration réelles, panne isolée visible et aucune clé étrangère supprimée ; sessions appareils toujours fonctionnelles.
- **Hors périmètre :** Ne pas lancer de nettoyage global Redis ou migrer la queue dans ce commit.
- **Sortie :** résultat et preuve consignés dans le TODO ; commit limité à cette tâche si la création de commits est autorisée ; arrêter la session de travail sur ce ticket, sans commencer le suivant.

## R05.02

**Titre de commit proposé :** feat(queue): process jobs through an isolated Redis worker

- **Entrée :** R05.01.
- **Travail limité :** Basculer la queue dans les environnements concernés et vérifier un vrai worker séparé avec effet PostgreSQL committé ; diagnostic réservé au test.
- **Validation exigée :** Job Redis exécuté et résultat relu depuis une nouvelle connexion ; job lié à une transaction annulée sans effet indu.
- **Hors périmètre :** Ne pas construire notifications métier ou outbox maintenant.
- **Sortie :** résultat et preuve consignés dans le TODO ; commit limité à cette tâche si la création de commits est autorisée ; arrêter la session de travail sur ce ticket, sans commencer le suivant.

## R05.03

**Titre de commit proposé :** test(queue): verify bounded retries and failed jobs

- **Entrée :** R05.02.
- **Travail limité :** Définir tentatives, attente et délais cohérents ; tester échec puis reprise ; vérifier les limites du worker Windows.
- **Validation exigée :** Échec enregistré après un nombre fini de tentatives ; absence de boucle ; résultat de reprise vérifiable.
- **Hors périmètre :** Ne pas faire échouer des jobs de développement existants.
- **Sortie :** résultat et preuve consignés dans le TODO ; commit limité à cette tâche si la création de commits est autorisée ; arrêter la session de travail sur ce ticket, sans commencer le suivant.

## R05.04

**Titre de commit proposé :** feat(health): report readiness without leaking infrastructure details

- **Entrée :** R05.03.
- **Travail limité :** Séparer liveness, readiness PostgreSQL/Redis et observation worker ; corréler les erreurs avec réponses publiques minimales.
- **Validation exigée :** Panne isolée produit la réponse attendue dans un délai borné ; reprise vérifiée ; aucune donnée de connexion divulguée.
- **Hors périmètre :** Ne pas créer d’endpoint public de lancement de jobs ou de commandes.
- **Sortie :** résultat et preuve consignés dans le TODO ; commit limité à cette tâche si la création de commits est autorisée ; arrêter la session de travail sur ce ticket, sans commencer le suivant.
